# RAG System Experimentation Summary

## 🎯 Goal

Improve the quality of answers generated by the local LLM (`ibm/granite4:350m-h`) in the CloudBees CI RAG system through systematic experimentation.

## 📚 Documentation

- **`EXPERIMENTS.md`**: Comprehensive list of 14+ experiments with implementation details
- **`FORK_SETUP.md`**: Step-by-step guide to fork and set up experimentation environment

## 🚀 Quick Start: Top 3 Experiments to Try First

### 1. Prompt Engineering (Easiest, High Impact)

**What**: Try different prompt templates (few-shot, chain-of-thought, role-based)

**Why**: Can significantly improve answer quality with minimal code changes

**Time**: 1-2 hours

**Files to modify**: `ollama_client.py`

---

### 2. Multi-Query Retrieval (Medium Effort, High Impact)

**What**: Generate multiple query variations and retrieve from each

**Why**: Better retrieval coverage, finds relevant docs even with different wording

**Time**: 2-3 hours

**Files to create**: `experiments/multi_query.py`

---

### 3. Reranking (Medium Effort, High Impact)

**What**: Use cross-encoder to rerank retrieved chunks

**Why**: More relevant context = better answers

**Time**: 2-3 hours

**Files to create**: `experiments/reranker.py`

---

## 🔬 Recommended Experimentation Workflow

```
1. Fork/Copy Project
   └─> See FORK_SETUP.md

2. Choose First Experiment
   └─> Start with #1 (Prompt Engineering)

3. Implement Experiment
   └─> Create experiment class
   └─> Modify core files or create new ones

4. Test on Sample Queries
   └─> Use tests/test_queries.json
   └─> Compare with baseline

5. Measure Results
   └─> Citation accuracy
   └─> Keyword coverage
   └─> Answer quality

6. Iterate or Move to Next
   └─> If promising: refine
   └─> If not: try next experiment
```

## 📈 Success Metrics

Track these for each experiment:

- **Citation Accuracy**: % of citations that match actual sources
- **Keyword Coverage**: % of expected keywords found in answer
- **Answer Length**: Words (longer often = more detailed)
- **Response Time**: Latency (should stay reasonable)
- **User Satisfaction**: Subjective quality rating

## 💡 Pro Tips

1. **Start Simple**: Begin with prompt engineering - it's the easiest win
2. **Test Systematically**: Use the same test queries for all experiments
3. **Document Everything**: Keep notes on what works and what doesn't
4. **Combine Experiments**: Once you find good ones, try combining them
5. **Measure Before/After**: Always compare against baseline
